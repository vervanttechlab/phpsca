Day 1 — PHP + MySQL Command Playbook

Vanilla OOP PHP edition. Same milestones as the Node/Express Day 1: environment, folders, git, and documentation — no npm, no Composer, no framework.

Before You Start

This is the PHP + MySQL version of the Day 1 command playbook. Same goals as the Node/Express edition — environment, folders, git, and documentation before any application code — but there is no npm here. Vanilla PHP needs no package manager and no build step: you write a .php file, and the server runs it.

WHY VANILLA, WHY OOPNo Composer, no framework (no Laravel, no Slim). Every class is one you write yourself, autoloaded by a nine-line autoloader you also write yourself. This mirrors exactly what the Node edition does with Express by hand: routes, middleware, controllers, one shared DB connection — just in PHP's own OOP syntax instead of JavaScript.

Terminal & Local Server Choice

OptionUse when
PHP built-in server (php -S localhost:3000 -t public)Recommended. No Apache/XAMPP config needed, starts in one command, same one used throughout this playbook.
XAMPP / Apache + a virtual hostIf the assessment machine already has XAMPP running Apache. Point the vhost's document root at this project's public/ folder.

Either way, MySQL still comes from XAMPP (or a standalone MySQL install) — only the PHP half changes.

WINDOWS 11: USE GIT BASHEvery command block in this edition is written for Git Bash (mkdir -p, touch, cat << 'EOF', grep). Unlike the Node edition, no PowerShell or CMD alternatives are given here, so open Git Bash and stay in it for the whole session.

Phase 1. Start the Project with ScaPExpress, Then Verify PHP & MySQL

CRITICALDo this while you still have the assessor's attention to ask about the machine's setup, before you are on your own. The project folder is created by the ScaPExpress extension in VS Code, not by hand — the manual commands are kept at the end of this phase only as a fallback.

Step 1. Create the Project Folder: ScaPExpress → Initialize Project

  1. Open VS Code with no folder open (File → New Window, or just start it).
  2. Press Ctrl+Shift+P to open the Command Palette.
  3. Type scapexpress — four commands appear. Select ScaPExpress: Initialize Project (autoload.php only).
  4. A folder picker opens: Where should the project live? Navigate to Desktop and click Use this folder.
  5. Project folder name: replace the default with tesda-backend-api-php and press Enter.
  6. Pick Create a new folder named tesda-backend-api-php.
  7. autoload.php opens in the editor and a message appears bottom-right. Click Open project. VS Code reloads with Desktop\tesda-backend-api-php as the workspace.
RUN IT NOWThe Explorer (left panel) shows exactly one file: autoload.php. That is the whole result of this step, on purpose — it is the PHP equivalent of the Node edition's mkdir + npm init -y: one folder, one file that everything else needs.

Step 2. Create the Folder Structure: ScaPExpress → Create Folder Structure

  1. Press Ctrl+Shift+P again.
  2. Type scapexpress and select ScaPExpress: Create Folder Structure (empty files).
  3. Main resource you will CRUD: keep item and press Enter.
  4. A message reports how many files were created. Click OK / dismiss it.
RUN IT NOWThe Explorer now shows the full tree from Phase 3: database/, docs/, public/, src/Core, src/Config, src/Controllers (empty), src/Middlewares, plus .env, .env.example and .gitignore. Open src/Core/Router.php: it is fully written. Open src/Config/Database.php: it is empty. Open public/index.php: a comment names the snippet that fills it. That split is deliberate — the plumbing PHP lacks is given to you; everything project-specific is still yours to type on Day 2.
THE ONE RULE FOR SNIPPETS IN .php FILESThe file must already start with <?php on line 1, and you type the prefix on the line below it. VS Code treats everything before <?php as HTML and shows no PHP snippets there — a test.php containing only api/register shows nothing at all. The placeholders the extension writes already have the tag; src/Config/Database.php is the one file that comes empty, so type <?php, Enter, then sx-db. Typing the / in api/register closes the popup: keep typing (api/reg) or press Ctrl+Space, or use the slash-free alias sx-register.

Step 3. Open the Terminal Inside VS Code and Confirm PHP & MySQL

Everything from here on is typed in VS Code's own terminal so it always starts in the project folder: Ctrl+` (the key under Esc), or Terminal → New Terminal. If it opens PowerShell, click the ▾ next to the + in the terminal panel and choose Git Bash; then click ▾ → Select Default Profile → Git Bash so every new terminal is Git Bash too.

terminal

php -m | grep -i pdo
"php: command not found" ON A XAMPP MACHINEXAMPP installs PHP and MySQL but does not put them on the PATH. If php -v or mysql is not recognized, add them for this Git Bash session before going on (every php and mysql command in both playbooks depends on this):
Git Bash
export PATH="/c/xampp/php:/c/xampp/mysql/bin:$PATH"
php -v
mysql --version

To make it permanent: Windows Settings → System → About → Advanced system settings → Environment Variables → edit Path → add C:\xampp\php and C:\xampp\mysql\bin, then reopen Git Bash.

Expected: a PHP 8.x version line, and pdo_mysql somewhere in the module list. If pdo_mysql is missing, enable it in php.ini (XAMPP's php.ini has it commented out by default with a leading semicolon on extension=pdo_mysql) and restart the server.

Step 1b. Create a Dedicated Database User (Not Root)

Then update .env: DB_USER=tesda_app and DB_PASS=ChangeThisPassword123! (matching whatever password you used).

Phase 4. Technical Documentation Generation

Same four files as the Node edition, same purpose, adjusted for PHP's own commands.

File 1. SYSTEM_ARCHITECTURE.md

docs/SYSTEM_ARCHITECTURE.md
cat << 'EOF' > docs/SYSTEM_ARCHITECTURE.md
# System Architecture

## Architectural Pattern
This project follows a 3-Tier Model-View-Controller (MVC) architecture, in vanilla
object-oriented PHP (no framework):
1. Presentation Layer: Client / Postman (HTTP Requests)
2. Application Layer: PHP front controller (public/index.php), Router, Middlewares, Controllers
3. Data Layer: MySQL via PDO

## Request Flow
[Client] -> [public/index.php] -> [Router] -> [AuthMiddleware] -> [Controller] -> [PDO/MySQL]

## Why a front controller
PHP has no built-in router the way Express does. Every request that is not a static
file is sent to public/index.php by .htaccess (Apache) or by `php -S` itself (built-in
server), and index.php's own Router class matches the method and path to a Controller.
EOF

File 2. SETUP_INSTRUCTIONS.md

docs/SETUP_INSTRUCTIONS.md
cat << 'EOF' > docs/SETUP_INSTRUCTIONS.md
# Setup & Execution Guide

## Prerequisites
- PHP 8.1+ with pdo_mysql enabled
- MySQL Engine / XAMPP (running on localhost:3306)

## Steps to Run Application
1. Copy .env.example to .env and fill in your DB credentials.
2. Import database/schema.sql into MySQL.
3. From the project root: php -S localhost:3000 -t public
4. Base URL: http://localhost:3000
5. Browser view: http://localhost:3000/items.html

# API Endpoint Specifications

## Base URL: http://localhost:3000/api/v1

| Endpoint | Method | Auth | Description |
| :--- | :--- | :--- | :--- |
| /auth/register | POST | None | Create new user account |
| /auth/login | POST | None | Authenticate user and get JWT token |
| /items | GET | Public | Retrieve all items (supports ?search, ?category_id, ?min_price, ?max_price) |
| /items/summary | GET | Public | Category totals via GROUP BY / HAVING |
| /items/:id | GET | Public | Retrieve single item by ID |
| /items | POST | Bearer JWT | Create a new item inside a transaction |
| /items/:id | PUT | Bearer JWT | Partial update via COALESCE |
| /items/:id | DELETE | Bearer JWT | Delete item |
EOF

File 4. TROUBLESHOOTING.md

docs/TROUBLESHOOTING.md
cat << 'EOF' > docs/TROUBLESHOOTING.md
# Troubleshooting Guide

| Error | Cause | Resolution |
| :--- | :--- | :--- |
| SQLSTATE[HY000] [2002] Connection refused | MySQL server stopped | Start MySQL via XAMPP Control Panel. |
| Address already in use :::3000 | Port in use | php -S localhost:3001 -t public |
| 401 Access Denied: No Token Provided | Missing JWT | Include `Authorization: Bearer <token>` in header. |
| Class "App\...\" not found | Autoloader can't find the file | Check the file lives at src/<Namespace path>.php matching the class name exactly. |
| SQLSTATE[HY000] [2002] No such file or directory | macOS/Linux: PDO tried a Unix socket XAMPP does not expose | Set DB_HOST=127.0.0.1 in .env. |
| 'php' is not recognized / command not found | XAMPP does not add PHP to PATH | export PATH="/c/xampp/php:/c/xampp/mysql/bin:$PATH" in Git Bash. |
EOF
